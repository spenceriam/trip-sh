# README Structure Instructions

This document defines the required structure for `README.md` files in projects that follow tucker-protocol.

## Required Sections (in order)

1. **Badges**
   - Tech stack indicators.
   - Version badge.
   - Build status if applicable.

2. **Screenshot or GIF Placeholder**
   - A visual preview of the application or an explicit placeholder if not available.

3. **What**
   - A concise description of what the project is.

4. **Why**
   - The problem the project solves.

5. **Who**
   - The target audience or users.

6. **Clone and Run Instructions**
   - How to set up the project locally.
   - Key commands to run the app and tests.

7. **Contributing**
   - Guidelines for external contributors.
   - Any project-specific contribution rules.

8. **License**
   - The license used by the project.

9. **Contact**
   - A way to reach the maintainer. For Spencer's projects, use: https://x.com/spencer_i_am

## Notes

- Maintain a professional tone and avoid emojis.
- Keep sections focused and free of unnecessary marketing language.
- When generating or updating a README, ensure sections appear in the exact order above.
